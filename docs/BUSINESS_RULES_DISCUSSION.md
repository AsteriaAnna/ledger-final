# 星账｜业务规则

本文是当前产品行为依据，其他核心文档只表达本文，不另行决定业务。当前只有设计和参考实验，没有已验收应用。

## 1. 产品范围与业务模块

目标：看清实际账户的钱、资金归属和性质；便捷记账；通过官方账单补全、核对，减少遗漏与重复。

| 模块 | 职责 |
|---|---|
| M1 身份与关系 | 登录身份、关系绑定、本人写与对象只读权限 |
| M2 账户与资金归属 | 实际账户、初始状态、份额与手动分配 |
| M3 交易账务 | 收入、支出、内部转账、独立退款、编辑删除与资金规则 |
| M4 导入与来源证据 | 官方文件、来源档案、映射、匹配去重、逐行结果与核对 |
| M5 预算与统计 | 个人净花销、日均、预测、预算及双方资金展示 |

页面可调用多个模块。M4不写第二套账务，M5不维护第二份余额。手机与桌面共享业务规则，首发须有可用的移动端核心体验。

V1支持实际现金/储蓄账户、普通收支、无手续费内部转账和独立退款。亲情卡、花呗及其他负债消费/还款不在当前支持范围，来源保留并标记不支持。不开发负债账户、截图识别、多币种、透支、解绑、账户删除、回收站或复杂异常中心。带费用转账本期不自动入账，不强行把两端金额写成等额。

## 2. M1：身份与关系

- 服务端验证登录身份，不能用客户端user_id授权。
- 每人只写自己的账本；绑定后可看对象账户、资金、账单，不能替对象新增、编辑、删除或导入。
- 账户写权限与资金归属分开；对象存款在本人账户不授予对象写权限。
- 原始文件、对方账号、来源观察和导入批次仅本人可读，对象账单只读不包含整份来源证据。
- 绑定须有效凭据；生成、传递、过期、防重用由认证实现负责。无解绑功能。

## 3. M2：账户与资金分配

### 3.1 实际账户和起始状态

账户对应银行卡、微信零钱、支付宝余额或现金，不创建虚拟共同账户。允许份额：本人流动资金、本人存款、绑定对象存款；不允许对象流动资金。份额均非负，合计等于账户余额。

各账户独立设置起始日期、初始余额和初始份额，份额合计等于初始余额，不计收入。交易记账日期早于该账户起始日：保存历史交易和消费统计，不影响该账户余额/份额；当日及以后正常生效。内部转账两端分别判断，不能丢弃整个历史交易。

### 3.2 手动分配与存款基准

同账户可用资金在合法份额之间等额调整，不改变总额，不计收支或真实转账；真实账户之间移动另记内部转账。

每个存款份额的基准=该份额初始分配+有效手动分配调整净额。当前份额从全部有效资金变动计算，缺口=max(基准−当前存款,0)。这是已有记录的派生值，不增设目标存款表。手动调整同时改变基准和当前份额；支出/回补不改变基准。基准只决定回补上限，不代表债务，不重写历史交易。

### 3.3 统一资金处理

| 操作 | 处理 |
|---|---|
| 普通支出、支出金额增加 | 本人流动资金→本人存款→对象存款 |
| 普通收入 | 增加本人流动资金 |
| 独立退款、支出金额减少 | 补对象存款缺口→补本人存款缺口→剩余加本人流动资金 |
| 内部转账 | 仅本人流动资金直接参与，两端等额，保留资金归属 |

未绑定没有对象份额。支出使用存款后提示使用了多少，不阻塞、不自动创建债务。需转存款时先手动调为流动资金，系统不擅自调整性质。

回补用操作时当前状态，不读取原消费，不重算后续交易。任何新增、撤销或修改若使余额/份额不足或为负，整笔失败，不允许半笔保存或透支。

## 4. M3：交易生命周期

### 4.1 类型

income普通收入；expense支出；transfer仅本人账户之间转账；refund官方来源的独立退款。平台文字“转账”不直接等于transfer，向他人转出可为支出、收他人转入可为收入。

手动新建仅income、expense、transfer；refund须由M4提供官方来源、经M3创建，不能手动新建或将普通交易改为refund。

### 4.2 独立退款

- 不关联原消费，不校验原消费累计退款上限，不级联删除。
- 读取实际到账账户、金额和官方时间；商户退款与转账退回均增加账户，不计普通收入。
- 商户退款默认抵减花销，转账退回默认不抵减；用户可编辑抵减开关。
- 记账日期默认官方时间，可编辑；抵减按记账日期月份。官方原始时间只读保留，不随编辑或重导改变来源身份。
- 按§3.3回补；累计退款状态只作证据，不替代每行金额、不另造退款。

例：8月消费100，9月退款30，默认8月花销100、9月抵减30。将退款记账日期改到8月，8月净花销70；关闭抵减只保留到账。

### 4.3 编辑与删除

- 日期、金额、账户、分类、商户、备注按API白名单编辑，保留交易ID；已有官方refund保持类型和来源子类型，不变成普通收入。
- 支出金额增减只处理差额；收入/退款改金额或账户，原子撤销自身旧影响再处理新事实，不能套支出扣减算法。
- 普通类型变更先撤销旧影响再执行新规则；改transfer须明确两端并满足流动资金条件。
- 仅改抵减开关只更新统计；仅改日期且不跨任一账户起始日，保留资金份额计划，仅改生效日/统计月份。跨起始日则原子撤销或生成本交易有效影响。
- 记账时间不得晚于当前时间；月份与日期按北京时间。撤销无法保证非负时整笔拒绝，不自动重算后续全部交易。
- 删除只撤销当前交易；消费不级联退款。来源证据保留、解除当前关联；新导入操作可恢复已删除交易。
- 重导不覆盖用户编辑；来源自身重要事实变化时展示差异，由既有编辑动作处理。

## 5. M4：官方导入

### 5.1 唯一链路

读文件/原始证据→识别平台与所有明细→确定来源账号档案→标准化语义→映射实际账户→检查稳定来源/同事件候选→可入账行调用M3→逐行结果与汇总→具备资格时核对手动账单。

“读出字段”不是“入账成功”。不支持、待处理或失败行保留证据，不调用M3。

### 5.2 来源身份与账户

- 来源档案是导出微信/支付宝账号；Account是钱实际在哪里；行渠道映射连接两者。
- 昵称仅作展示，支付宝文件头账号标识可辅助匹配本人档案。首次创建，多个候选不明时选择一次；后续复用。
- 来源身份=内部档案+完整官方交易单号；单号作文本，商户单号可空/重复，不作主键。
- 映射按档案隔离，两个微信账号零钱不能串用；跨平台银行卡经本人确认可指向同一Account，尾号不作全局身份。
- 支付红包只标优惠，剥离后找实际账户；普通支付行金额按用户确认即实际变动，不额外扣优惠。人与人微信红包仍为交易。
- “已存入零钱”能确定到账微信零钱；不能所有空渠道都填零钱。账户证据冲突待处理。

### 5.3 类型与状态

等待确认收货不阻止已支付支出；失败/关闭不产生资金影响。原消费显示已退款仍保留原支出，由独立退款行抵减一次。

微信普通转账角色不明时仅要求选择收入、支出或本人内部转账；已明确普通消费不逐笔确认。无费充值/提现按类型推断两端角色，两端Account仍须确定。带费用转账明确unsupported，不猜净额、不硬套等额转账。

支付宝分类映射内部受控代码；微信商户/商品规则可给候选，无可靠分类用other，不阻塞正确金额和账户，不用AI决定账务。

### 5.4 重试、重导与匹配

- 同幂等键相同请求重放原结果，同键不同请求拒绝。用户新导入用新键；同文件可复用解析但须检查当前关联，不能永远跳过。
- 来源已关联有效交易不重建；关联为空（未成功或被删除）重新评估；补映射后恢复待处理来源。
- 每次观察保留，旧导出不覆盖新状态；同导出时间事实冲突待处理。仅履约状态变化不再入账；无交易且从失败变有效可重新创建。
- 来源与手动账单弱字段相似仅给候选，确认后关联同一事件；refund不能关联原消费expense。不同平台疑似同一内部转账也只给候选，不能按两个来源直接重复记两笔。
- 新来源与已有交易在北京时间同一天、实际账户/方向/最终类型/金额一致时生成候选；单候选也不静默认定。已有稳定来源关联优先，不受用户改日期影响。

### 5.5 缺失核对

全量标记、声明/实读一致、必要身份/时间完整、来源账号/实际账户明确且语义支持，才具备核对资格。实际核对终点不晚于导出时间。

V1保守处理：任一行不支持、待处理或解析失败，本批次不自动生成缺失核对项，但其他可入账行正常处理。不同平台可用同一卡，仅凭Account不能断言手动交易应在本文件出现。银行卡手动交易须明确来源档案；微信零钱/支付宝余额的唯一已确认档案可用于判断。已有官方来源的交易不再生成缺失提示。

核对项按档案+手动交易唯一，重叠导入复用；提供保留并标记已核对，或删除手动交易。保留不改账，删除调用M3并原子关闭核对项；后续匹配来源自动结案。不自动删交易。

## 6. M5：首页统计与预算

未绑定展示本人流动/存款，绑定后同屏展示本人流动、本人存款、对象流动、对象存款。按资金归属汇总，不把代管资金当自己所有；对象消费不占本人预算。

个人净花销=expense−启用抵减的refund；income、transfer不计花销，refund不计普通收入。净花销可负，不截断。剩余=max(预算−净花销,0)，超支=max(净花销−预算,0)。预算按个人与月份管理。

当前月截至今天，日均=截至今天净花销/已过自然日数（含今天）；历史月用全月天数。上月日均用完整上月；变化率=(当前日均−上月日均)/上月日均，分母0返回null，不输出无穷值。当前月预测=未提前舍入日均×全月天数；历史月预测等于整月实际。overview限当前/过去月份，预算允许合法未来月份。

所有金额存整数分；日均/预测四舍五入到分，变化率四位小数，中间不先舍入。退款改日期/抵减开关同时更新涉及月份预算、日均、预测。M5只读M3交易与M2/M3有效资金结果。
