## 4. 工作方式

1. 每次只实施一个有明确验收标准的任务。
2. 任务必须指向业务规则、逻辑模型、API 契约和具体模块边界。
3. 先复现或定义验收场景，再改代码；禁止为“夯实基础”无限扩大任务。
4. 每次交付记录修改文件、测试命令/结果、已知限制和下一步。
5. 只有实际运行并通过验收的功能才标记完成；文档推演不算功能验收。
6. 发现与冻结规则冲突时，先记录复现条件、受影响规则与最小修正方案，不静默改变产品行为。
