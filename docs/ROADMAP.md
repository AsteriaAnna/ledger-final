**首发产品约束：** 必须能在移动端顺畅完成核心记账；桌面端与 Android 端共享业务能力、API 契约和数据规则。双人绑定与对象只读查看属于首发验收范围，数据归属和服务端权限从第一阶段开始落实。截图识别仍暂缓，不作为移动端记账体验的前置条件。

另外，以下属于具体实现前的规则缺口，而非重新讨论整个产品范围：

- 退款到账账户不同于原消费账户、或原消费为信用消费时，资金份额如何恢复。
- 导入后核对项如何持久化确认，并避免重叠导入范围反复提示。
- 官方退款来源无法确认原消费时，如何通过独立解析动作完成确认；不把退款来源直接链接到原消费。
- 修改账户记账起始日期时，如何原子重建该账户相关资金变动。
- 关系绑定凭据的生成、过期、验证和防重复使用方式。
- 微信/支付宝真实文件中的稳定交易 ID、覆盖范围、状态与退款字段；不提前冻结具体匹配算法。

详情见 IMPLEMENTATION_PLAN.md。

## 4. 工作方式

1. 每次只实施一个有明确验收标准的任务。
2. 任务必须指向业务规则、逻辑模型、API 契约和具体模块边界。
3. 先复现或定义验收场景，再改代码；禁止为“夯实基础”无限扩大任务。
4. 每次交付记录修改文件、测试命令/结果、已知限制和下一步。
5. 只有实际运行并通过验收的功能才标记完成；文档推演不算功能验收。
6. 发现与冻结规则冲突时，先记录复现条件、受影响规则与最小修正方案，不静默改变产品行为。
