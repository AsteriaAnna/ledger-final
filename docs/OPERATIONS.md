# 运行、发布与恢复

本文件描述现有代码的实际运行和维护步骤。业务与公开接口仍分别由业务规则和`openapi.yaml`定义；阶段验收状态以[实施计划§2.6](IMPLEMENTATION_PLAN.md#26-阶段控制与当前进度)为准。

## 当前可运行范围

M1–M5的24个公开操作已接入本地Web/API，连接现有`writter-dev` PG。云端保留应用迁移，业务与Auth测试夹具已清理；没有公开上线的Web/API。不要将静态托管的名义域名当作已发布网址，其根路由目前关闭。

在项目根目录使用Node 24.15.0 / npm 11.12.1执行`npm ci`，再执行`npm run build`。本轮已在无私有配置的干净检出中安装、构建并运行针对性测试。Web生产构建仍有CloudBase SDK包体提示；依赖审计有ExcelJS间接uuid的两个中度提示，已核对只调用无参数v4，不进入公告涉及的v3/v5/v6路径。未用强制降级解析器绕过公告。

本地将两份`.env.example`复制为各自目录下的`.env.local`并在私有位置填配置。后端Key只填API，Web仅填publishable key。启动`npm run dev:api`和`npm run dev:web`，默认Web通过Vite代理连接3000端口。不要把真实Key、原始账单、备份、带令牌的HTTP捕获提交到仓库。

## API配置与凭据

| 变量 | 要求 |
|---|---|
| `CLOUDBASE_ENV_ID` | 当前只允许既有`writter-dev-d0g7h1prq4ce60665`；地域为上海 |
| `CLOUDBASE_API_KEY` | 完整后端Key，须能调用既定业务RPC；脱敏列表值不能用。Web SDK不作为无Key时的伪运行时凭据备用通道 |
| `CURSOR_SECRET` | 生产必须至少32字符随机值，私有保存并跨进程/部署保持稳定。轮换后端Key时不应连带让所有游标失效 |
| `NODE_ENV` | 正式运行填`production`，缺Key或游标签名配置会立即拒绝启动 |
| `PORT` | 整数1–65535；平台端口必须与此一致 |
| `WEB_ORIGIN` | 真实Web的完整来源，含协议与必要端口；浏览器跨域需匹配，不填通配符 |
| `LEDGER_CONTRACT_PATH` | 默认按API目录定位`../../openapi.yaml`；自定义工作目录时显式传完整路径 |

后端Key没有浏览器用户身份；API每次先经官方Auth核实令牌sub，再向受限RPC传入该主体。普通用户及后端角色均无应用表直接读写权，函数属主内核负责账务原子提交。开发Key的有效期不等于正式运行周期；发布前在私有管理端确认到期和轮换方式。轮换先注入新Key、验证一次受限RPC，再撤销旧Key，不能把Key写进构建产物。生产超时/限频不能伪装成用户登录过期。

## 构建包与发布限制

API构建后，可在项目根运行`node tools/release/package.mjs tmp/api-release-<唯一名称>`，生成新目录。脚本只复制锁文件、API编译产物、包清单、公开契约及空配置样例，不复制私有配置、账单、恢复工具或测试。进入输出目录执行`npm ci --omit=dev --workspace apps/api`，注入配置后从`apps/api`运行`node dist/server.js`。

本轮实际验证独立包安装、启动、固定健康响应、未登录401、缺后端Key及缺生产游标签名时拒绝启动。构建包是准备产物，**不等于云端部署通过**。Web需在确定真实HTTPS API来源后填写`VITE_API_BASE_URL`重新构建；发布后须验证真实登录、写入与整页刷新。

2026-10-28已集中核实：

- 现有环境为个人版，超限按量关闭；CloudRun未开通，云函数数量为0，静态根路由关闭。没有改套餐、加环境或启用持续收费服务。
- [官方云托管限制](https://docs.cloudbase.net/run/limitation)明确CPU/MEM不包含在云开发环境套餐，需开启超限按量；包体20M、超时60秒。当前费用约束不允许直接开通。
- [云函数请求体错误说明](https://docs.cloudbase.net/error-code/EXCEED_MAX_PAYLOAD_SIZE)列其他类型包体上限6MB，与现行10MiB同步XLSX上传契约不兼容。不能部署后把上传限制偷偷缩小，也不能将分块/存储中转当作现有契约已验收。

因此现阶段保留本地可运行版本和发布包。继续正式上线前，必须解决“现有预算内可承载10MiB同步请求的运行入口”；若改用套餐外云托管或调整上传通信方案，需要用户决定相应费用或契约变化。现在不购买、不启用超限按量，也不发布一个上传链路已知不完整的入口。10000行真实云端耗时和两份官方原件复测仍待验，不能以本地时间代替。

## 备份与回滚

[应用恢复演练工具](../tools/recovery/README.md)记录一次真实云端一致快照导出→独立本地数据库恢复。覆盖17张应用表、原始字段/来源观察、用户sub映射、关系、资金、版本、请求重放与序列；逐行和结构/权限均一致，恢复后读写及同键重试正常。没有将同一PG实例内新schema当作独立恢复。

本轮快照只含合成数据，留在私有`tmp/recovery`。正式备份应加密且离线保管，先验证恢复再清源数据。CloudBase Auth账号/凭据、PG存储对象、托管/路由/密钥和平台回档不包含在此次演练；每日加密备份、保留7份、RPO/RTO目标仍未实证，P7不能标通过。

已应用迁移不可改写。应用代码回退不自动撤销数据库迁移；破坏性操作前先做可恢复备份，新迁移优先保持已发布API兼容。当前PR全部保留草稿堆叠，`main`未被本轮提交或合并。
