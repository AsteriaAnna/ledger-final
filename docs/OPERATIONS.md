# 运行、发布与恢复

本文件描述现有代码的实际运行和维护步骤。业务与公开接口仍分别由业务规则和`openapi.yaml`定义；阶段验收状态以[实施计划§2.6](IMPLEMENTATION_PLAN.md#26-阶段控制与当前进度)为准。

当前只有两个人低频记账，容量上限不等于日常负载。后续数据验证按实施计划的最新约束仅在本地执行，不安排云端合成导入、远端SQL/RPC、登录探针或压测来消耗资源点。既有云端验证是历史证据，不能当作继续测试的授权；未测的云端能力保持待验，不能用本地结果替代。正常使用也不能被用作合成测试的名义。

## 当前可运行范围

M1–M5的24个公开操作已接入本地Web/API，连接现有`writter-dev` PG。云端保留应用迁移，业务与Auth测试夹具已清理；没有公开上线的Web/API。不要将静态托管的名义域名当作已发布网址，其根路由目前关闭。

在项目根目录使用Node 24.15.0 / npm 11.12.1执行`npm ci`，再执行`npm run build`。本轮已在无私有配置的干净检出中安装、构建并运行针对性测试。Web生产构建仍有CloudBase SDK包体提示；依赖审计有ExcelJS间接uuid的两个中度提示，已核对只调用无参数v4，不进入公告涉及的v3/v5/v6路径。未用强制降级解析器绕过公告。

本地将两份`.env.example`复制为各自目录下的`.env.local`并在私有位置填配置。后端Key只填API，Web仅填publishable key。启动`npm run dev:api`和`npm run dev:web`，默认Web通过Vite代理连接3000端口。不要把真实Key、原始账单、备份、带令牌的HTTP捕获提交到仓库。

## API配置与凭据

| 变量 | 要求 |
|---|---|
| `CLOUDBASE_ENV_ID` | 当前只允许既有`writter-dev-d0g7h1prq4ce60665`；地域为上海 |
| `CLOUDBASE_API_KEY` | 完整后端Key，须能调用既定业务RPC；脱敏列表值不能用。Web SDK不作为无Key时的伪运行时凭据备用通道 |
| `CURSOR_SECRET` | 生产必须至少32字符随机值，私有保存并跨进程/部署保持稳定。轮换后端Key时不应连带让所有游标失效 |
| `NODE_ENV` | 正式运行填`production`，缺Key或游标签名配置会立即拒绝启动 |
| `PORT` | 整数1–65535；平台端口必须与此一致 |
| `WEB_ORIGIN` | 真实Web的完整来源，含协议与必要端口；浏览器跨域需匹配，不填通配符 |
| `WEB_DIST_PATH` | 可选，仅指向本次Web构建目录；同源包从API目录运行时填`../web/dist`。留空则维持API独立运行 |
| `LEDGER_CONTRACT_PATH` | 默认按API目录定位`../../openapi.yaml`；自定义工作目录时显式传完整路径 |

后端Key没有浏览器用户身份；API每次先经官方Auth核实令牌sub，再向受限RPC传入该主体。普通用户及后端角色均无应用表直接读写权，函数属主内核负责账务原子提交。开发Key的有效期不等于正式运行周期；发布前在私有管理端确认到期和轮换方式。轮换先注入新Key、验证一次受限RPC，再撤销旧Key，不能把Key写进构建产物。生产超时/限频不能伪装成用户登录过期。

## 构建包与发布限制

API构建后，可在项目根运行`node tools/release/package.mjs tmp/api-release-<唯一名称>`，生成新目录。脚本只复制锁文件、API编译产物、包清单、公开契约及空配置样例，不复制私有配置、账单、恢复工具或测试。进入输出目录执行`npm ci --omit=dev --workspace apps/api`，注入配置后从`apps/api`运行`node dist/server.js`。

本轮实际验证独立包安装、启动、固定健康响应、未登录401、缺后端Key及缺生产游标签名时拒绝启动。构建包是准备产物，**不等于云端部署通过**。Web需在确定真实HTTPS API来源后填写`VITE_API_BASE_URL`重新构建；发布后须验证真实登录、写入与整页刷新。

双人轻量模式新增可选同源包：构建后执行`node tools/release/package.mjs tmp/ledger-release-<新名称> --with-web`，一次打包网页与API，同一个服务返回首页、指纹资源和原24个API，不新增另一后端。Web构建的`VITE_API_BASE_URL`留空；平台Auth的来源配置仍需要正确设置。首页/账本响应不缓存，不存在的API不会变成网页；私有配置和上传文件没有文件读取入口。[部署目录](../cloudbase/deploy/README.md)保存Dockerfile和运行说明，根`.dockerignore`限制构建上下文。

本轮已实际启动独立同源输出包，核对首页/指纹JS、健康与未登录401、私有路径404，包内无私有`.env`。本地HTTP→原PG迁移链路完成两人绑定、本人记账和同键重试、刷新余额、对象只读与拒写、预算/统计，12份HTTP请求响应通过唯一OpenAPI校验；Auth和云网关均为本地显式替身，异常外部请求被阻断，CloudBase网络调用0。API22项针对性测试通过。未打开浏览器运行真实SDK登录，也未做云端验证。本机没有Docker/Podman，镜像构建、Linux运行和平台端口/路由保持待验，不能把Node输出包通过写为镜像部署通过。

2026-10-28已集中核实：

- 现有环境为个人版，管理端回读`EnvDeductionMode=credits`、`EnableOverrun=false`；CloudRun未开通，云函数数量为0，静态根路由关闭。没有改套餐、加环境或启用持续收费服务。限定EKS的本周期查询返回CPU/内存/流量累计0，不代表其他模块未使用，也不能当成实际剩余点数。
- **更正此前费用判断：**[云托管限制页](https://docs.cloudbase.net/run/limitation)仍写CPU/MEM不在套餐、需超限按量，但与[2026-10-26更新的资源点价格文档](https://cloud.tencent.com/document/product/876/127357)及[云托管计费FAQ](https://docs.cloudbase.net/run/faq/fee)冲突。新价格表明确上海PG支持云托管，CPU55点/(核·小时)、内存32点/(GiB·小时)、外网800点/GB，按套餐→资源包→按量扣除。当前环境正是资源点模式，不能继续把“云托管必然套餐外付费”当作已证实阻塞。具体开通路径能否保持超限按量关闭仍需核实；不能为通过开通擅自开该开关。
- [云函数请求体错误说明](https://docs.cloudbase.net/error-code/EXCEED_MAX_PAYLOAD_SIZE)列其他类型包体上限6MB，与现行10MiB同步XLSX上传契约不兼容。不能部署后把上传限制偷偷缩小，也不能将分块/存储中转当作现有契约已验收。

现阶段优先评估现有资源点套餐内的单个CloudRun服务，保留原24操作和10MiB契约，不因旧限制页直接改为云函数或缩小上传上限。候选规格0.25核/0.5GiB、最小实例0、最大1；仅计算CPU/内存为29.75点/实例小时，连续运行30天为21420点。该算例不含数据库、流量、认证和日志，不是本月总价或剩余额度承诺；缩容也有平台空闲等待时间，不能把一次请求时间等同计费时长。不得新增环境、改套餐或开启超限按量。

## 设计、契约与实际体积复核

复核日期2026-10-28，代码基线`f09c21d`。原业务是个人/双人账本、官方账单补全和来源核对；`10MiB/10000行/同步完成`是现有接口能力承诺，不是已证实的真实文件体积或独立资金规则。原两份169行官方文件目前不在工作区，不能用合成文件宣称真实原件已测。

| 对象 | 本地实测 | 与托管的关系 |
|---|---:|---|
| Web生产构建全部3文件 | 1121694字节，约1.07MiB | 静态托管文件，不是云函数的请求体 |
| API验证包（已安装生产依赖） | ZIP11909606字节，约11.36MiB；解压约39.55MiB | 低于官方通用代码包50MB档；具体平台打包/运行时适配仍须实测。不能拿6MB请求上限判定代码放不下 |
| 169行合成XLSX / 实际multipart体 | 22587 / 22919字节 | 当前解析器可读；不是原169行官方原件 |
| 1000行合成XLSX / multipart体 | 97525 / 97857字节 | 大约0.093MiB，远小于6MB |
| 10000行合成XLSX / multipart体 | 929391 / 929723字节 | 大约0.887MiB；行数不能直接当文件体积 |
| 同三档输入生成的PG RPC JSON | 235888 / 1390990 / 13928002字节 | 最大约13.28MiB，原字段和规范化候选会放大；不是再次经云函数入站。通用非函数请求100MB文档只作参考，不冒充PG专属入口实测 |

以上文件/JSON测量使用现有正式解析器、11列合成官方结构及不同单号/金额/时间。不是最坏上界或内存用量证明。只做本地运算，云端写入0。

本地PGlite执行原迁移，169行全部入账约0.445秒、1000行全部入账约6.327秒；解析分别32/48毫秒，10000行只测解析329毫秒，**没有测10000行入账**。首次合成数据同额同日触发同事件候选，不能算全入账耗时；随后改为逐笔不同金额并严格核对created=行数后才记录本表。时间不含真实共享PG、鉴权、网络和冷启动，不能写为云端验收。

容量复核时API→PG统一12秒超时；轻量运行增量已将导入上传/继续处理/核对写入预算调整为45秒，普通读取保持12秒，为现有60秒入口留出鉴权/解析余量。入口对整批调用一次`sl_import_upload`，该函数逐行子事务处理后整批提交，并非每行一个HTTP请求。延长等待没有证明10000行能完成，同步全批汇总不能通过只处理前几百行、GET继续写账或虚构202任务绕过；断连/超时不自动重写，继续沿用原幂等键确认结果。

可行路线顺序：

1. **优先保持契约，按双人低频负载评估单服务。**CloudRun保留为候选，最小0/最大1实例也只是待核实的配置，不自动开通。数据解析、SQL热点、超时协调和恢复继续在本地处理；取消原计划的169行/较大合成输入云端验证。云端实际链路与耗点尚未实测的部分保留待验，不为完成验收数字消耗资源点，也不提前购买常驻、高并发或额外环境。
2. **HTTP云函数是有条件备选。**包体本身未超部署档，但不能保证所有合法10MiB文件通过6MB入站。只有真实文件需求支持更小上限且用户接受明确契约变更时，才按带multipart/编码余量的安全边界调整，不能简单把文件上限写成6MB。
3. **确需更大文件再评估私有存储中转。**可避开函数直接接文件，但会改变上传请求/文件权限/清理流程；同步处理时限仍在，不能把它当作免费解决全部限制。

本轮只读核对环境与EKS用量，未开通计算资源、改费用开关或修改业务/OpenAPI。结论是已有保留原设计的可行候选，尚未证明所有上限已兑现；不是已上线，也不是已证明必须升级套餐。

## 备份与回滚

本轮快照只含合成数据，留在私有`tmp/recovery`。正式备份应加密且离线保管，先验证恢复再清源数据。CloudBase Auth账号/凭据、PG存储对象、托管/路由/密钥和平台回档不包含在此次演练；每日加密备份、保留7份、RPO/RTO目标仍未实证，P7不能标通过。

已应用迁移不可改写。应用代码回退不自动撤销数据库迁移；破坏性操作前先做可恢复备份，新迁移优先保持已发布API兼容。当前PR全部保留草稿堆叠，`main`未被本轮提交或合并。
