# 星账 · ledger-final

私人账本与财务洞察。产品重点是实际账户管理、交易账务、官方账单导入，以及在保留个人账本边界的前提下进行双人只读查看。首发必须保证移动端核心记账体验；桌面端与 Android 端共用业务能力、API 契约和数据规则。

## 当前状态

仓库当前处于**产品与工程设计准备阶段**。当前冻结业务规则为 v2.6；逻辑数据模型 v0.3、API 契约 v0.2、工程模块边界 v0.2 和实施计划 v0.2 均为候选文档，不代表已有可运行应用或 API 服务。请勿将文档中的示例响应视为已部署功能。

## 文档优先级

1. 核心业务规则决定已确认的产品行为。
2. 逻辑数据模型表达这些规则需要的数据概念和不变量，不擅自改变业务范围。
3. API 契约把业务操作转成前后端约定；候选接口不得被当作已实现 API。
4. 工程模块边界和实施计划约束代码职责与开发顺序。
5. 路线图只记录真实状态；不能把计划、推演或文档完成写成软件功能已完成。

若发现文档间存在冲突，应指出具体章节和场景，先提出最小修正，再继续相关开发，不要自行选择一份文档覆盖其他基线。

## 协作方式

- 每个实现任务都要有目标、允许修改范围、验收标准和测试结果。
- 优先完成一条端到端可验证的业务路径，再扩展下一项。
- 账务写入必须经过统一业务规则与原子事务边界；前端和导入解析器不得直接修改余额。
- 每次交付说明修改文件、实际运行的测试、失败/未覆盖场景和下一步。
- 未经明确要求，不扩大到截图识别、负债账户、透支管理、解绑或复杂异常中心。
